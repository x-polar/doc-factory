# KORI Answers — 유통 시나리오: 상품·행사 인사이트 Q&A

> **타깃**: 대형 유통(이마트) · **대상 조직**: 상품기획(MD)·영업전략·점포운영

## 고객의 문제

- 상품 마스터·행사 이력·매출 데이터는 BI에, 행사 기획서·운영 매뉴얼·VOC는 문서함에 — **숫자와 맥락이 분리**되어 있어 "왜"에 답하려면 사람이 취합
- MD 순환보직으로 카테고리 노하우 단절 — "작년 이 시즌 무엇을 왜 했고 결과가 어땠나"를 아는 사람이 없음
- BI 대시보드는 **정해진 질문**에만 답함 — 자연어로 묻는 탐색형 질의(비교·원인·이력)는 데이터팀 티켓 대기
- 상품·거래처 정보는 영업 기밀 — 부서·직급별 접근 통제 하에서만 조회 허용

## 대표 시나리오

> **Q. "작년 추석 델리 카테고리 행사 성과 요약하고, 이번 추석 기획서와 비교해서 리스크 짚어줘."**

| 단계 | KORI 동작 | 담당 구성요소 |
|---|---|---|
| 1 | 질의 해석 — 카테고리 코드·행사 유형·사내 용어를 도메인 사전으로 정규화 | Domain Dictionary |
| 2 | 매출·행사 실적을 정형 조회 (부서 권한은 SQL 파라미터 바인딩으로 강제) | Quantitative Retriever |
| 3 | 작년 행사 기획서·결과 보고서·VOC에서 맥락 검색 — 권한 필터 선적용 | Lexical + Semantic Retriever, ACL pre-filter |
| 4 | 실적 수치 + 기획 의도 + VOC를 융합, 올해 기획서와 항목별 비교·리스크 도출 | Fusion & Rank, Agent Orchestrator |
| 5 | 수치는 조회 결과만 인용(할루시네이션 차단), 전 과정 감사 로그 | Deterministic Security Layer |

## 왜 범용 Agent Harness로는 안 되는가

- **정형+비정형 융합**: "얼마 팔렸나"(BI)와 "왜 그랬나"(문서)를 한 답변으로 — 대시보드도 범용 RAG도 못 하는 교집합
- **수치 신뢰성**: 매출 숫자를 LLM이 생성하면 사고 — 정형 조회 결과만 인용하도록 결정적으로 제한
- **유통 도메인 사전**: 카테고리 체계·행사 유형·마진 용어 등 사내 코드 체계가 정확도의 관건
- **평가 체계**: 골드 질의 기반 회귀 평가로 시즌 개편·데이터 변경 후에도 품질 유지 검증

## 도입 제안 (PoC 8~10주)

카테고리 1개(예: 델리/가공식품) 범위 — ①행사 기획서·결과 보고서 인제스천 + 상품/행사 용어 사전 구축 → ②매출 데이터 read-only 연동 → ③MD 골드 질의 50문항 평가 → 정답률·수치 정합성 리포트로 검수.
