# KORI Answers — 제조 시나리오: 공정 트러블슈팅 어시스턴트

> **타깃**: B2B 부품 제조 — 반도체(삼성전자), 자동차 부품(현대모비스) · **대상 조직**: 공정/품질/설비 엔지니어링

## 고객의 문제

- 불량 이력·8D 리포트·설비 매뉴얼·ECN(설계변경 통보)이 수십 년치 축적되어 있으나, **검색 가능한 지식이 아니라 폴더 속 문서**로 존재
- 베테랑 엔지니어 은퇴와 함께 트러블슈팅 노하우가 소실 — "이 불량 코드, 예전에 어떻게 잡았지?"에 답하는 시스템 부재
- 수율·불량률 등 **정형 데이터(MES/ERP)와 비정형 문서(리포트·매뉴얼)가 분리**되어 있어, 원인 분석 시 사람이 양쪽을 오가며 수작업 취합
- 국가핵심기술 보안 요건: 외부 AI 서비스 사용 불가, 협력사·부서별 도면/스펙 접근 통제 필수

## 대표 시나리오

> **Q. "3번 라인 A-204 불량이 이번 주 급증했는데, 과거 유사 사례와 조치 이력 알려줘."**

| 단계 | KORI 동작 | 담당 구성요소 |
|---|---|---|
| 1 | 질의 해석 — 사내 불량코드·공정 약어를 도메인 사전으로 정규화 | Domain Dictionary |
| 2 | MES에서 해당 라인·기간 불량률 추이를 정형 조회 (권한은 SQL 파라미터 바인딩으로 강제) | Quantitative Retriever |
| 3 | 과거 8D 리포트·트러블슈팅 문서에서 유사 사례 검색 — 조회 전 사용자 권한 필터 적용 | Lexical + Semantic Retriever, ACL pre-filter |
| 4 | 정형 수치 + 문서 근거를 융합해 원인 후보·과거 조치·담당 부서를 **원문 인용과 함께** 답변 | Fusion & Rank, Agent Orchestrator |
| 5 | 답변 검증 — 근거 없는 주장 차단, 전 과정 감사 로그 기록 | Deterministic Security Layer |

## 왜 범용 Agent Harness로는 안 되는가

- **정형+비정형 융합 질의**: 수율 데이터 조회와 문서 검색을 하나의 답변으로 합성하는 것은 RAG 템플릿 밖의 영역
- **도메인 사전**: 불량코드·공정 약어(CMP, EDS, PR 등)·사내 용어는 어떤 LLM에도 없음 — 사전 품질이 곧 정확도
- **완전 온프렘 + 결정적 통제**: 모델·검색·데이터 전부 사내망, 권한은 LLM 판단이 아닌 코드로 집행
- **평가 체계**: 골드 Q&A 셋 기반 회귀 평가로 "정확도를 어떻게 보증하나"에 수치로 답변

## 도입 제안 (PoC 8~10주)

특정 공정 1개 라인 범위 — ①불량 이력·매뉴얼 인제스천 + 도메인 사전 시드 구축 → ②MES read-only 연동 → ③현업 엔지니어 골드 질의 50문항 평가 → 정답률·근거 인용률 리포트로 검수.
