# KORI Answers — 건설 시나리오: 안전·시방 규정 Q&A

> **타깃**: 종합 건설·플랜트 EPC(현대엔지니어링) · **대상 조직**: 현장 안전관리·공무·설계/시공 엔지니어링

## 고객의 문제

- 프로젝트당 도면·시방서·계약서·안전관리 문서 수만 건 — 현장에서 필요한 조항을 찾는 데 걸리는 시간이 곧 리스크
- **중대재해처벌법** 이후 "이 작업의 안전 기준·유사 사고 사례"가 경영진 직접 관심사 — 그러나 근거 문서는 본사 서버 깊숙이
- 발주처 클레임·설계변경 분쟁은 결국 **문서 싸움** — 계약서·시방서·회의록 교차 확인에 며칠 소요
- 문서 형태가 최악의 난이도: 스캔 도면, HWP 시방서, 복잡한 표·단면도 — 일반 RAG 파서로는 품질이 나오지 않음

## 대표 시나리오

> **Q. "OO현장 지하 굴착 구간, 흙막이 가시설 관련 시방 기준과 최근 유사 사고 사례·조치 기준 알려줘."**

| 단계 | KORI 동작 | 담당 구성요소 |
|---|---|---|
| 1 | 질의 해석 — 공종·공법 용어를 건설 도메인 사전으로 정규화 | Domain Dictionary |
| 2 | 해당 현장 시방서·설계도서에서 관련 조항 검색 — **현장/발주처별 문서 격리** 적용 | Retrieval Layer, ACL pre-filter |
| 3 | 안전 규정·사내 사고 사례 DB에서 유사 사례 검색 | Lexical + Semantic Retriever |
| 4 | 시방 조항 + 법규 + 사례를 **조항 번호·원문 인용과 함께** 종합 답변 | Fusion & Rank, Agent Orchestrator |
| 5 | 안전 관련 답변은 **근거 인용 없으면 출력 차단** — 전 과정 감사 로그 | Deterministic Security Layer |

## 왜 범용 Agent Harness로는 안 되는가

- **인제스천이 곧 진입장벽**: 스캔 PDF·HWP·도면·표 범벅 문서의 파싱 품질이 답변 품질의 80%를 결정 — 해외 스택이 가장 취약한 지점
- **틀린 답 = 산업재해**: "그럴듯한 답변"이 아니라 **조항 단위 근거 강제**가 필요 — LLM 신뢰가 아닌 결정적 검증으로 집행
- **현장·발주처별 격리**: 프로젝트 간 기밀(견적·공법) 교차 노출 차단을 검색 이전 단계에서 코드로 보증
- **감사 추적**: 사고 조사·클레임 대응 시 "누가 언제 어떤 근거로 어떤 답을 받았나" 전체 재현 가능

## 도입 제안 (PoC 8~10주)

진행 중 현장 1개 범위 — ①시방서·안전 문서 인제스천(HWP/스캔 포함) + 공종 용어 사전 구축 → ②안전관리팀 골드 질의 50문항 평가 → 정답률·조항 인용 정확도 리포트로 검수. 확산 단계에서 전사 사고 사례 DB·계약 문서로 확장.
