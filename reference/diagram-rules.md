# Diagram Rules — 메인 아키텍처 다이어그램 표준 규칙

KORI Answers 메인 다이어그램(2026-08, 커밋 ~50회 왕복)에서 확정된 규칙.
**새 다이어그램(드릴다운 포함)은 이 규칙을 기본값으로 시작한다** — 같은 시행착오 반복 금지.
계약·컴포넌트 정의는 `diagram-catalog.md`, 브랜드 토큰은 `brands/<brand>/diagram.css`.

## 1. 텍스트·라벨

- **노드 = 이름만.** 설명(dg-s)은 기본 생략 — 상세는 드릴다운 슬라이드로.
  설명이 꼭 필요한 핵심 노드만 예외(예: 게이트웨이·오케스트레이터).
- **핵심 노드 설명은 리스트(dg-items).** 산문/구분자(·) 나열보다 체크리스트.
  인접 노드끼리 리스트 항목 수 균형 고려(예: CG 4개 ↔ AO 5개).
- **긴 컴포넌트 이름은 `<br>` 2줄로** (Model Gateway, Agent Orchestrator 등).
  같은 존 안에서는 줄 수 통일(전부 1줄 또는 전부 2줄).
- **존 라벨은 제목만.** 부제·컴포넌트 나열 금지 ("Model Zone — 온프렘/외부 API…" ✗).
- **레이블 영어 전용** (D24). 제품명(LiteLLM 등)은 본문 레이블 금지, 로고 배지만.
- **네이밍 품사 통일**: 파이프라인 단계는 공정 명사(-ing/-ion) — Conversion·
  Chunking·Indexing·Summarization (D30). 행위자 명사(Converter) 혼용 금지.
- **전문용어는 청중 기준으로.** 내부 용어(Context Slots)보다 업계 표준
  (Grounding Context) 우선 (D31). "이게 무슨 뜻?"이 나오면 이름이 틀린 것.
- 스텝 번호(①②③), 범례, ⇄ 마커: **기본 넣지 않는다.** 필요하면 나중에 추가.

## 2. 관계선

- **라벨은 최소.** 팬아웃 선(툴→스토어 등)은 라벨 없음. 존 사이 대표 선에만
  1개(예: "OpenAI Compatible API"). 크기 10px(brands/kori-answers/diagram.css).
- **방향성**: 데이터 접근(툴↔스토어)은 화살촉 없는 무향선. 호출 흐름만 화살촉.
- **색 규칙**: 런타임 사용자 경로 + 모델 호출 = 민트(accent) / 데이터 접근 =
  그레이 / 적재·배치 = 점선(e--flow), Load는 민트 점선.
- **교차 0 원칙**: 소스 노드의 세로 순서를 타깃 노드 순서와 일치시켜 해결한다.
  (Tool Layer 순서를 스토어 순서에 맞춰 재배열해 교차 제거 — D32)
- **트렁크 종단은 존 경계**: 여러 대상에 쓰는 선(Load)은 개별 노드가 아니라
  존 경계에서 끝낸다.
- SVG 텍스트 라벨은 z1이라 노드(z2)에 가려진다 — **노드 근처 라벨은 z3 div로**.
- 라벨은 선의 위/아래·좌/우 여백에 배치, 두 줄 나눔(`Tool<br>Invocation`)으로
  화살표와의 겹침 회피.

## 3. 레이아웃·정렬

- **좌→우 단방향 스토리**: 진입 액터(좌) → 게이트웨이 → 코어 → 툴(세로 스택)
  → 스토어(우측 세로 열). 팬아웃은 가로 평행선이 되게 세로 스택을 우선 검토.
- **존 중앙 정렬**: 존 안 단일 노드는 세로 중앙, 복수 노드는 상하 여백 균등.
- **존 크기는 내용에 맞게 타이트하게** — 빈 여백이 크면 존 폭/높이를 줄인다.
  단, 노드 간격이 답답하면 존을 키운다(앰버 h 38→44→49% 반복 확장 사례).
- **인접 영역 정합**: 세로 열(Data Stores)의 상~하단을 이웃 영역(앰버+Ingestion)
  범위와 일치시키면 정돈돼 보인다.
- **대칭 진입점**: 런타임(End User)과 배치(External Interface) 액터는 같은
  좌측 레벨·같은 스타일(ghost)로 상하 대칭 배치.
- 존 라벨(칩형)은 **존 상단 경계선이 라벨 세로 중앙을 지나게** 걸친다.

## 4. 색·브랜드

- 다크가 마스터. **라이트 변형은 별도 파일**(`*-light.html`)로 파생:
  - `<style>` 스코프 오버라이드 + `.dg-light` 마커 클래스, `:has()` 셀렉터.
  - 민트 `#22FFBD`는 라이트에서 대비 부족 → **딥 그린 `#0B9E74`** 치환(전역 replace).
  - 회색 외곽선/연결선/존 경계는 라이트에서 잉크 비율 상향(42/68/52%).
  - 화살촉 그레이 `#8A8A8A` → `#3D4A45`.
  - 푸터 화이트 로고는 `filter: invert(1)`.
- 푸터 = XENOIMPACT 로고만(`theme.yaml logo.footer`), 크기 `.ftr .logo-sm`
  0.78u(기본의 절반).

## 5. 워크플로

- **반복 단위**: 수정 → 렌더 → PNG(fitz, dpi 130) → vision 검증 → 커밋·푸시.
  수정마다 이미지를 사용자에게 제시. 겹침/잘림은 vision으로 반드시 확인.
- **좌표 수정 시 연결선 동반 수정**: 노드를 옮기면 그 노드에 닿는 선의
  시작/끝점(viewBox 좌표)도 같은 커밋에서 갱신.
- **정의서 동기화**: 다이어그램 구조 변경은 정의서에 D번호로 같은 커밋에 기록.
- 편집은 python replace 스크립트(문자열 anchor) — missed 목록을 출력해 anchor
  불일치를 즉시 감지한다. 셸 heredoc에 `&`가 들어가면 터미널 툴이 거부하므로
  `&` 포함 편집은 스크립트 파일로 저장 후 실행.
- 중간 확정 시점마다 `release/`에 PDF 스냅샷 저장(LFS).
